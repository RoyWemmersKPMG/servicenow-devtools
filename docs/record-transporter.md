# Record Transporter

ServiceNow source control transports application files derived from `sys_metadata`, not arbitrary business/configuration data. Record Transporter wraps selected data records in `x_snc_devtools_transporter_record`, which is application metadata, and groups them in `x_snc_devtools_transporter_package`.

Use it only for small, deliberate, versioned configuration datasets. Do not use it for transactional data, bulk migration, secrets, users, attachments, or records whose target ownership is unclear.

## Create and pack a package

1. Switch to the application scope that should own the package.
2. Open **DevTools > Packages** and create a package.
3. Set a stable ID suffix, descriptive name, description, order, and the auto-unpack/auto-commit behavior required by the release.
4. Add a packaging function to the owning application.
5. Reset the package, query the authoritative records, and pack each record:

   ```javascript
   (function packDemoConfiguration() {
       var packageId = 'x_your_scope.demo';
       x_snc_devtools.RecordTransporterPackageReset(packageId);

       var gr = new GlideRecord('x_your_scope_configuration');
       gr.addActiveQuery();
       gr.orderBy('name');
       gr.query();
       while (gr.next()) {
           x_snc_devtools.RecordTransporterRecordPack(packageId, gr);
       }
   })();
   ```

Reset is important: it preserves deletion intent for records that were in an earlier package version but are no longer selected. Review the resulting package records before committing.

## Unpack during installation

Use `InstallerAPI.RecordTransporterPackageUnpack()` from the target application's `AppInstall()` or configure auto-unpack as appropriate. The installer should run after required tables, columns, and referenced records exist.

Test four cases:

- clean target with no prior records;
- target with matching records;
- target with locally modified conflicting records;
- upgrade where a previously packed record has been removed.

Define whether source-controlled package data wins over local changes and make that policy visible to operators.

## Pack an update set

On a completed update set, select the **Transporter Package Application**, then use **Pack Update Set into Record Transporter**. DevTools creates ordered packages, enables installation-time unpack/commit behavior, and records technical debt.

Use this only when there is no feasible application-file representation. Inspect sibling update sets, ordering, target collisions, and backout before baselining.

## Operational safeguards

- Never pack credential or connection-secret fields.
- Use narrow, deterministic queries and stable sys_ids.
- Keep package ordering explicit where references exist.
- Review delete actions generated by a reset.
- Run in a clone and compare before/after record sets.
- Include package behavior in release notes and ATF coverage.
